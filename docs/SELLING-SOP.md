## 2. 发码流程（核心运营动作）

发码本质就是调你 Worker 的 `/admin/issue`，拿一个 `HM-XXXX-XXXX-XXXX`，给买家。

### 2.1 单个发码（手动单 / 测试）

```bash
curl -X POST https://<your-worker>/admin/issue -H "x-admin-secret: <你的ADMIN_SECRET>"
# → {"key":"HM-A1B2-C3D4-E5F6"}
```

### 2.2 批量预生成（给「自动发货」备货）

爱发电/淘宝的自动发卡，需要你**事先准备一批授权码**导入平台卡密池。下面是基于现有 Worker 逻辑的批量发码脚本框架（Node，跑在你本机；不新增后端代码，纯调现有 `/admin/issue`）：

```js
// gen-codes.mjs —— 批量生成 N 个授权码，输出到 codes.txt
// 用法： node gen-codes.mjs 50
const WORKER = "https://<your-worker>";        // 你的 Worker 根地址
const ADMIN  = process.env.ADMIN_SECRET;        // 别硬编码，用环境变量传
const n = Number(process.argv[2] || "10");

import { writeFile } from "node:fs/promises";

const keys = [];
for (let i = 0; i < n; i++) {
  const resp = await fetch(`${WORKER}/admin/issue`, {
    method: "POST",
    headers: { "x-admin-secret": ADMIN },
  });
  const { key, error } = await resp.json();
  if (error) { console.error("发码失败：", error); break; }
  keys.push(key);
  console.log(`[${i + 1}/${n}] ${key}`);
}
await writeFile("codes.txt", keys.join("\n") + "\n", "utf8");
console.log(`已写入 codes.txt，共 ${keys.length} 个`);
```

运行：

```bash
# Windows PowerShell：先设环境变量再跑，避免口令进命令历史
$env:ADMIN_SECRET = "<你的口令>"
node gen-codes.mjs 50
```

> 原理：每次 `/admin/issue` 都会在 KV `LICENSES` 里写一条
> `{ devices: [], plan: "lifetime", createdAt }`，并返回随机 `HM-XXXX-XXXX-XXXX`。
> 这些码在被买家激活前一直是「未绑定」状态，可以放心预生成囤着。
> **`codes.txt` 是你的库存，别外泄**——泄露等于送出授权。

### 2.3 把卡密导入平台 / 发给买家

- **爱发电自动发货**：在商品的「自动发放内容」里，把 `codes.txt` 的码逐行导入卡密池。买家付款后平台自动取一条发给他，并显示在订单详情/发到邮箱。
- **淘宝自动发卡**：用店铺的「自动发货」或第三方发卡插件，导入同一批码。
- **手动单（微信/咸鱼）**：买家付款截图确认到账后，从 `codes.txt` 划掉一条发给他，并在自己的台账标注「码→买家→日期→平台订单号」。

### 2.4 买家拿到码后怎么用（你要写进商品说明/自动回复）

> 1. 安装 Homepage Modules 插件并启用。
> 2. 打开插件设置页，把授权码 `HM-XXXX-XXXX-XXXX` 粘进激活框，点「激活」。
> 3. 提示「激活成功」即解锁。一个授权码最多 3 台设备，断网也能用。

### 2.5 退款 / 换设备 / 售后处理

| 场景 | 处理方式 |
|---|---|
| **买家要退款（未激活）** | 平台退款。该码还没绑设备，可回收：从台账标记作废，或直接 `/admin/revoke` 吊销，避免被白嫖激活。 |
| **买家要退款（已激活）** | 数字商品默认「已激活不退」，先在商品页声明清楚（见第 4 节合规）。确需退则 `/admin/revoke` 吊销 + 平台退款。注意：已离线激活的设备不会实时失效，详见第 3 节。 |
| **换电脑 / 超了 3 台** | 现有后端**没有「解绑单台设备」接口**，只能整码吊销后重发新码：`/admin/revoke` 旧码 → `/admin/issue` 发新码给他。正版用户换机属正常需求，态度好点直接换。 |
| **买家说码无效** | 先确认他没打错（全大写、连字符对）；再确认你发的是新版「能激活」的 Release；最后 `curl /activate` 用该码自测端点是否正常。 |
| **恶意退款/勒索差评（咸鱼常见）** | 留好聊天/订单证据走平台申诉。这也是推荐爱发电、慎用咸鱼的原因。 |

> 工具提示：若想要「换设备自助解绑」「查某码绑了几台」这类能力，当前 Worker 还没有对应端点，需要日后给 `server/src/worker.js` 加 `/admin/unbind`、`/admin/inspect` 之类管理接口。起步阶段用「吊销+重发」足够。

## 3. 防盗版的现实预期（先说清楚，别自欺）

这套授权是**离线签名令牌**方案，安全边界要诚实认知：

- **客户端可破解**：`main.js` 是 JS，懂行的人可以改掉 `LicenseManager.evaluate()` 的判定、或塞个 `devUnlock`，本地解锁。**任何纯前端插件都拦不住这点。**
- **离线令牌无法实时吊销**：令牌一旦签发并本地验签通过，断网照用；你 `/admin/revoke` 只能拦「新设备激活」，拦不了已激活的老设备。
- **能拦住什么**：① 随手把码发到群里被陌生人无限激活——3 台上限 + 设备指纹绑定挡住了；② 普通用户没能力也没动力去改 JS。

**目标定位**：抬高门槛 + 把正版用户服务好，而不是追求绝对 DRM。
真正让人付费的是——更新维护、答疑、新模块、社群，而非「破解不了」。把精力放在产品和服务上，比和盗版死磕更划算。

## 4. 定价、促销与合规

### 4.1 定价（围绕 59 元买断）

- **正价**：¥59 永久买断，含 3 台设备、后续更新。这是主锚点。
- **早鸟价**：上线首 2 周或前 100 名 **¥39 / ¥49**，营造稀缺、攒首批口碑和评价。明确写「早鸟结束恢复 59」。
- **组合优惠**：
  - 「插件 + 1.4万词词库 / 配套资料」打包微溢价（如 ¥79），提升客单。
  - 老用户带新「双方各得小额优惠 / 额外资料」。
  - 社群/学校批量（如 10 份）给折扣价，批量用 `gen-codes.mjs` 一次出码。
- **不建议**搞复杂订阅；个人小工具买断更省心、退款纠纷也少。

### 4.2 促销话术要点

- 突出**省下的时间 / 能力**（30 个模块、1.4 万词、AI 多服务商、错词本），而不是单纯「便宜」。
- 给**7 天免费试用**做钩子（插件本身就内置 7 天 trial），让人先用上瘾再付费。

### 4.3 合规提醒（必读，避免踩坑）

- **如实声明虚拟商品**：商品页明确写「本商品为**虚拟数字授权码**，非实物，发货即为发放授权码」。
- **退款条款写在前面**：明确「**授权码一经激活/发放，不支持退款**」（未激活可退则也写清），先声明再交易，能挡掉大量扯皮。也要遵守所在平台的消保规则，别和平台强制退款政策硬刚。
- **不夸大宣传**：别写「永不被破解」「100% 防盗」「官方认证」之类——既不实（见第 3 节），也可能违反广告/平台规则。如实描述功能即可。
- **第三方与版权**：确认插件用到的词库、图标、依赖授权允许商用；Obsidian 插件若也想上架官方社区市场，需符合其条款（商业插件政策另看官方规定）。
- **发票/税务**：随收入规模，注意个人经营所得的合规申报；走爱发电/淘宝有平台流水留痕，便于日后规整。
